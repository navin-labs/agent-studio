# SECURITY: threat model and mitigations

Scope: one operator (Navin), one Mac, local files, n8n in Docker, outbound calls to model, media, Telegram and YouTube. Audited against the code at the commit named in [proof/production-readiness-report.md](proof/production-readiness-report.md). "Tested" means a test in `npm run check` fails if the control breaks.

## Assets and boundaries
| Asset | Boundary that protects it |
|---|---|
| Publishing to a channel | Human approval (signed link or Telegram tap) -> ledger entry with the video's SHA-256 -> dispatch re-checks the file hash and the (channel, platform) destination |
| `.env` secrets (`APPROVAL_SECRET`, bot token, API keys) | git-ignored (`.env`, `*.env`, `token*.json`, `*.pem`...); only `.env.example` with placeholders is tracked; never logged |
| State (`state/ledger.jsonl`, fingerprints) | git-ignored, append-only JSONL, torn trailing line tolerated, mid-file corruption stops the run |
| The Mac | Approve receiver binds `127.0.0.1` only |

## Controls (verified in code; tested where noted)
- **Approval**: HMAC-SHA256 over channel, week, ids, approver, expiry; `timingSafeEqual`; secret shorter than 16 chars refused; strict parsing of every field before the signature is checked; expiry; a link works once (first 16 hex chars of its signature are stored in the ledger); a changed video needs a new approval (ledger stores `sha256`); failed-QA variants are held alone. Tested in `studio/approval.test.ts`.
- **Dispatch**: each variant goes only to its own (channel, platform) destination; unmanifested, misdirected, changed or already-queued variants are refused; an upload with an unknown outcome is never retried by itself (operator resolves it with a signed `--resolve`). Tested in `studio/dispatch.test.ts`, `telegram.test.ts`.
- **Single dispatcher**: `state/run.lock` (`wx` create, stale-pid takeover) in `studio/run.ts`.
- **HTML output**: the approval page escapes all interpolated text (`esc`).
- **Model calls**: `studio/costguard.ts` caps calls, wall-clock, prompt size, retries and spend; models run with an explicit tool allow/deny list; output is schema-checked and passes QA and approval before anything leaves the machine. Tested in `studio/costguard.test.ts`.
- **Media downloads** (`engine/src/lib/mediaHub.ts`, tested by `studio/mediahub.test.ts` against a local HTTP server and a local HTTPS server with a throwaway certificate): https on port 443 only, no URL credentials, host allowlist (unsplash, pixabay, archive.org, iconify, matched on a dot boundary); the name is resolved once per hop, every answer must be public (private, loopback, link-local, CGNAT, multicast, unparseable all refused), **and the connection is made to that validated address** (pinned through the request's `lookup`, TLS still checks the certificate against the name), so a DNS answer that changes after the check is never used; redirects followed by hand, at most 3, each hop re-checked for protocol, port, host and address (an https-to-http hop is refused); certificates are verified (an untrusted or wrong-name certificate fails); one 30 s timeout covers headers and the whole body; 40 MB cap for images (5 MB API JSON, 2 MB SVG) and 200 MB for videos, on the declared length and on bytes actually streamed, the stream cancelled and the partial file removed; image type from magic bytes, PNG canvases over 50 megapixels refused; the plate index written by rename. SVG props must be a plain `<svg>`: no script, handlers, foreignObject, animation, DTD/entities, CSS imports, external `url()` or non-fragment `href`.
- **ffmpeg never touches the network.** (Behaviour change: a video plate used to be fetched by ffmpeg with a range seek, moving only the seconds needed; it is now downloaded whole, up to 200 MB, then cut. Slower and heavier for big Internet Archive items, which over the cap are refused rather than trimmed remotely.) Videos are downloaded by the code above (capped, to disk), identified by their first bytes (mp4/mov or webm/mkv only; a playlist, concat list or text file is refused before ffmpeg starts), and cut from the local file with `-protocol_whitelist file` and the input format forced (`-f`), so no playlist demuxer is tried and `concat:`, `subfile:`, `data:`, `http:`, `https:`, `tcp:` inputs are refused (shown with the real Remotion ffmpeg). Arguments are an array (no shell); 5 minute timeout, SIGKILL.
- **Approve receiver** (`studio/approve-server.ts`, tested on a real socket by `studio/receiver.test.ts`): bound to 127.0.0.1; refuses any `Host` other than 127.0.0.1, localhost, host.docker.internal or [::1] (DNS rebinding), any request carrying an `Origin` header (a web page calling in), methods other than GET and POST, POSTs that are not `application/json` (a cross-site form or no-preflight fetch), and POSTs to unknown routes. POST bodies: declared length over 5 MB refused before reading; streamed bytes over the cap stop the read and close the socket; 30 s total deadline (a stalled or trickling client gets 408); a body cut short is dropped without a crash. Optional `LOCAL_API_TOKEN` (16+ characters, header `x-forge-token`, timing-safe compare) protects every route except `/health` and the self-signed `/approve`.
- **Ledger lock** (`withLedgerLock`, an exclusive SQLite transaction on `state/ledger.lock.db` via Node's core `node:sqlite`, no dependency): the approve receiver and the dispatch run are separate processes. Before this review an approval read the ledger, spent time hashing videos, then appended; a dispatcher claim written in between could be overwritten by "approved", re-opening an upload under way. Every append to `ledger.jsonl` goes through `appendLedger`, which takes the same lock (a static test fails if any other code writes the ledger or names the lock database; the lock is the same whatever the state path is spelled as). Approval, rejection, `resolve`, `markPublished`, every dispatch step and the claim are serialised, and the claim is a compare-and-set (it writes "dispatching" only if the ledger still holds the same approval hash). The operating system drops the lock the instant the holder dies, so there is no stale file, no takeover and no time-based expiry. Tested across real processes: 4 x 40 read-modify-writes lose no update; 4 processes tapping one link produce one approval per variant; a SIGKILLed holder frees the lock at once; a SIGSTOPped holder is not overtaken; a rival process that takes the approval back while a dispatch is deciding wins and nothing is sent.
- **Paid-call boundary** (`studio/budget.test.ts` traces it in the source): the Claude CLI is started in exactly one place (`claudeExec` in `costguard.ts`), reachable only through `CostGuard.call`, which the Director and the repair loop use. Calls run strictly one at a time (a queue), so every ceiling check sees what earlier calls spent: five calls fired together stop at the ceiling instead of each seeing the full allowance. A limit that is NaN, zero, negative or infinite is refused (it used to compare false with everything, i.e. no ceiling), `COSTGUARD_*` overrides are validated and capped (USD 25, 1 hour, 50 calls), and a caller cannot hand the executor a larger per-call budget (only the guard computes it). The only other paid endpoints in the code are the OpenAI and ElevenLabs TTS APIs in `make.mjs`: they now run only when `TTS_PROVIDER` names them (an API key in `.env` is not consent; the old code picked a provider from a key alone), and under a per-run character ceiling (`TTS_MAX_CHARS`, default 6000, at most 50000) checked before each request. Channel voices are local (free). **Not covered:** model calls made by agent sessions outside this repo's code (the Forge agent, a Claude Code session, Stitch/MCP tools) go through whatever limits those tools have, not this guard.
- **Model executor** (`studio/costguard.ts`, tested by `studio/modelcalls.test.ts` with a fake `claude` binary, no model contacted): output capped at 2 MB (a runaway session is killed), hung sessions killed at the remaining wall clock, garbage/empty/non-zero output becomes an error call (never a success), a missing CLI is a clear error, every failed attempt counts toward the 6-call ceiling so an always-failing call cannot loop, remaining budget and time (not the full allowance) are passed to each call.
- **QA file integrity** (`engine/scripts/probe.ts`): an mp4 must tile exactly and contain moov and mdat; unreadable files are a failed check, not a crash (`studio/render-integrity.test.ts`, real ffmpeg clip truncated several ways).

## Prompt injection and untrusted input
Feed items, webpages, captions and transcripts are data. The model cannot publish: it has no tool that reaches a platform, and every output goes through schemas, the art gate, QA and a human tap. File paths for plates come from the media hub, not from model text. Residual risk: a poisoned feed item can still shape a script's wording; the human reviewing the video is the control.

## Known limitations (not fixed; accepted or planned)
1. **Helper endpoints are open by default.** `/metrics`, `/experiment-days`, `/feed`, `/feeds`, `/metrics-due`, `/experiment-days-due`, `/packaging-check`, `/dispatch-check` need no secret until `LOCAL_API_TOKEN` is set, and **it is not set**: the 14 calls in the 7 live n8n workflows do not send `x-forge-token` (`node studio/n8n-compat.test.ts --require-token` exits 1) and the workflows were not changed. The receiver always refuses browsers, DNS rebinding and non-JSON POSTs, but not a local process or a container that can reach `host.docker.internal`. They cannot approve or publish; `/metrics` and `/experiment-days` can add rows for already-dispatched posts, and `/feed` fetches only feeds listed in `feeds`. Enabling procedure: n8n/README.md.
2. **Ledger lock: residual risk and operating constraint.** The previous file-based lock had a stale-takeover race (two processes judging the same stale file at once could both enter, and a holder stalled over two minutes lost its lock while still writing); a duplicate upload needed a re-render approval to land inside that window. It is replaced by the SQLite transaction lock, which removes both windows on one machine with a local disk. What remains: (a) it is a POSIX advisory lock, so it protects only code that uses it: the unlocked writers are the dispatch run's own later steps after its claim (dispatched, post URLs, claim release) and the metrics/experiment files, none of which read-then-decide on a state another process can change; hand-editing `ledger.jsonl` while the system runs is not covered; (b) it is for one machine and a local disk, not a network file system or two machines sharing `state/`; (c) a holder that stalls keeps the lock, so others wait up to 30 s and then fail with "ledger is locked by another process" (an approval is refused, a dispatch run stops and reports): safe, but it needs a person if the holder never returns (find it with `lsof state/ledger.lock.db`); (d) `node:sqlite` needs Node 22.5+ (older ones print an experimental warning); this repo runs Node 26. **Operating constraint:** the receiver and the tick must be restarted together on this code. A still-running receiver from before this change uses the old file lock, which does not exclude the new one; until both are restarted the two lock types do not protect each other. Run exactly one receiver and one tick (launchd does).
3. **Cost accounting.** A model call that is killed, times out or crashes without reporting its cost is booked at the budget cap it was given and marked `unknown` (never $0); a CLI that could not start is `none` (really $0). The cap is an upper bound only by the CLI's own flag, which has overshot before ($0.71 against a $0.20 flag). `reconcile` replaces an unknown figure with the one from the provider's usage page. Tested with a fake `claude`; the provider's real behaviour on kill is not.
4. **JPEG/WebP/GIF canvas size is not checked** before ffmpeg decodes them (only PNG headers are); the 5 minute timeout bounds the work. A video's decoded size is not checked either.
5. **Publishing outcome uncertainty** is handled by operator reconciliation, not automatically (see [RUNBOOK.md](RUNBOOK.md)).
6. **Mocked integrations**: n8n, Telegram, YouTube and the Claude CLI are exercised against fakes. Nothing here proves the live APIs behave the same today. The HTTPS tests use a throwaway certificate on localhost; the providers' real certificates and CDNs were not contacted.
7. **Creative review binding.** `filmSha` covers the film's own `.tsx` and the board, not shared render code (`fx/retention.tsx`, `composer/*`): a change to shared code does not invalidate earlier reviews. Widening it would invalidate every recorded review, so it was left and is recorded here. A review is also only as good as the process that produced it (the `review` command stamps the current hash onto whatever review file it is given).
8. Legacy ids kept on purpose because live workflows use them: n8n webhook paths `agent-studio-approve`, `agent-studio-youtube-<channel>`, `agent-studio-packaging-<channel>`, the n8n workflow names "agent-studio: ...", the Telegram alert prefix "agent-studio needs you" (matched by tests), `engine/package.json` name `reel-engine` (renaming touches the lockfile), the Writer agent prompt's `~/Dev/projects/agent-studio` path (the Forge agent's own machine path; not verified), and historical text in `docs/DECISIONS.md`, `docs/research`, `docs/proof`.

## Render fault injection: what is and is not simulated
Required assets (`engine/scripts/required-assets.mjs`, `make.mjs`): a music file the board names, the end-card mark, and for a live channel both brand audio files are REQUIRED. They are reported in a separate `fatal` list that `--force` does not apply to (`--force` skips only ordinary quality-gate errors); one of the audio pair alone is always fatal; only a channel that is not live may go without brand audio, with a warning. A channel with a voice configured cannot render in production with `--no-vo` or `VOICE` off (previews with `--out=` can), and a voiced line without a clip stops the render ("the voice engine wrote no clip for this line"; a failing, empty or garbage TTS also fails it). Proved by `studio/make-required.test.ts` against a temporary engine tree (`FORGE_TEST_ROOT`) with a fake TTS, with 5 mutants killed; nothing renders in those tests. A board with no channel voice (demo/test) may still render silent, with a warning. `FORGE_TEST_ROOT` is a test hook and must never be set in production. One quirk found: importing `mediaHub.ts` fills any EMPTY environment variable from the real `engine/.env` by name, so `VOICE=` does not turn the voice off (`VOICE=off` does).
Tested (`studio/render-faults.test.ts`, `studio/render-integrity.test.ts`, `studio/mediahub.test.ts`): ffmpeg missing, not executable, exiting non-zero, killed by a signal, hanging (SIGKILLed at the timeout, no orphan, also when it ignores SIGTERM), invalid arguments, input missing; a mastering pass that fails, hangs or writes nothing never replaces the good mp4 and leaves no `.master.mp4`; undecodable, empty, text, HTML and missing videos fail the motion and contact-sheet steps and keep the previous contact sheet; output directory missing or read-only; every literal `staticFile()` asset exists under `engine/public` (excluding `src/fx/demos`, whose demos read the git-ignored `public/hook-test/` folder: a clean clone cannot render those demos, found by this test); truncated, trailing-junk, header-only, zero-byte mp4 fail QA; QA failed, no QA, emptied, truncated, deleted video and missing manifest are all refused at approval and never reach the ledger.
**Tested through `make.mjs` itself:** the required-asset and voice rules above. **Not simulated, so not claimed:** the Remotion/Chromium render itself (font-load failures, `delayRender` timeouts, GPU/WebGL failures, a render killed half-way: the render writes the mp4 in place, and `make.mjs` deletes the old variant folder first, so a killed render leaves a partial folder that QA then fails); a real full disk (ENOSPC; the fake-ffmpeg test shows the message is passed through); killing the parent while it waits on ffmpeg (a `spawnSync` child is not guaranteed to be stopped when its parent is SIGKILLed; not tested); audio that is truncated or out of sync (only the presence of an audio stream, loudness and duration are checked); permission errors on the video file itself.

## Secrets practice
- Local only: `cp .env.example .env`, fill, never paste values into chat, tickets or logs. The approve server never logs query strings.
- Least privilege (target; the live OAuth scopes and n8n credentials were NOT inspected in this review, so verify them in the Google console and n8n): one YouTube credential per channel with only upload/analytics scopes; Telegram taps accepted from one configured chat id only (tested in `telegram.test.ts`).
- Rotation (manual, by the owner): generate a new `APPROVAL_SECRET` (16+ chars), restart the approve receiver and the n8n approval workflow; links signed with the old secret stop working, which is intended. Rotate Telegram/YouTube/media keys at the provider and update `.env`. This review rotated nothing.
- Secret scan at review time: tracked files searched for common key patterns (OpenAI/Google/Slack/GitHub/Telegram formats): no matches. Re-run: see the release checklist.
